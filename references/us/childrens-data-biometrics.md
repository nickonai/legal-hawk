# Children's Data & Biometrics — US (+ международная сводка)

> Профильный reference для продуктов, обрабатывающих **данные детей и/или биометрию лица** (особенно: AI-генерация изображений из фото, EdTech, детские приложения, персонализированные подарки с фото ребёнка). Последняя верификация: 2026-06.

## 0. Когда этот файл применим
Читай этот файл, если продукт: собирает/обрабатывает фото или данные детей (<13 / <16 / <18 в зависимости от закона); использует распознавание/генерацию по лицу; EdTech; персонализированные товары по детскому фото. Биометрия лица ребёнка = одна из самых засуженных зон (BIPA class actions).

---

## 1. COPPA (federal floor, США) — обновлён 2025
- **Закон:** Children's Online Privacy Protection Act, 15 U.S.C. §6501-6506; правило 16 CFR Part 312 (FTC COPPA Rule).
- **Амендмент 2025:** опубликован 22.04.2025, **вступил в силу 23.06.2025, полный дедлайн комплаенса 22.04.2026** (в силе).
- **Scope:** сервисы, «directed to children <13» ИЛИ с «actual knowledge» сбора ПД **от ребёнка <13**.
- **Personal information теперь включает биометрию** — прямо перечислены «facial templates / faceprints», голос, отпечатки, iris, gait, ДНК (для автоматического распознавания).
- **Ключевые новые требования:** (1) **отдельное VPC** (verifiable parental consent) перед раскрытием детских ПД третьим сторонам для «не-integral» целей; (2) FTC прямо: **передача детских данных на обучение AI НИКОГДА не «integral»** → нужен либо отдельный opt-in, либо (лучше) **no-training / zero-retention режим** у AI-провайдера; (3) обязательны **письменная data-retention policy** + **письменная information security program**.
- **VPC-методы (FTC-approved):** подписанная форма; кредитка/платёж с уведомлением; видеозвонок; гос-ID + face-match; «email plus». **Оплата картой родителем — один из валидных сигналов согласия.**
- **Нюанс «кто юзер»:** если **взрослый (родитель)** загружает данные ребёнка, а сервис **не позиционируется на детей как юзеров** (adult-facing, gift) — это сильный аргумент, что вы не «collect from a child». Дизайнить строго adult-facing + age-gate 18+ + аттестация «я родитель/опекун».
- **Штраф:** до **$53,088 за нарушение** (FTC Act civil penalty, индексируется).
- **Действие:** age-gate 18+; parental-consent/attestation gate ДО загрузки; no-training API-режим; письменные retention + security policy; не позиционировать на детей.

## 2. Биометрические законы штатов
### Illinois BIPA — ГЛАВНЫЙ class-action риск
- **Закон:** 740 ILCS 14. **Единственный** штат с **частным иском** (private right of action).
- **Требования:** §15(b) — информированное письменное **согласие ДО сбора**; §15(a) — публичная **retention/destruction policy**; §15(d) — согласие до раскрытия/передачи; запрет наживы на биометрии (§15(c)).
- **Штраф:** $1,000 (небрежность) / $5,000 (умысел) за нарушение + расходы на адвоката. **SB 2979 (2024)** убрал «per-scan» катастрофу (теперь одно нарушение на человека, не на каждое сканирование); ретроактивность подтверждена 7-м округом (2026).
- **Защита (важно для AI-likeness):** **решение 9-го округа по делу Zellmer (2024)** — «biometric identifier должен СЛУЖИТЬ идентификации». Если вы **не строите идентифицирующий face-template**, а генерите художественный likeness — сильный аргумент, что вы **вне BIPA**. НО: кейсы **Flora v. Prisma Labs (Lensa)** (фото→AI-аватар) показывают — иски подают всё равно; защита стоит денег.
- **«Не хранить фото» помогает частично:** снимает §15(a) (retention) + урон от утечки, **НЕ снимает** §15(b) (согласие до сбора) и §15(d) (раскрытие передачи). Нужно в связке: transient-фото + no-template + consent + disclosure.
- **Геофенс Illinois** — опциональный risk-trade, НЕ обязателен при корректной реализации согласия.

### Texas CUBI
- **Закон:** Tex. Bus. & Com. Code §503.001. Только AG-энфорсмент, **до $25,000 за нарушение**, частных исков нет.
- **TRAIGA / HB 149 (06.2025):** AI-исключение — если система **не используется для уникальной идентификации** конкретного человека, биометрические требования смягчены. В нашу пользу для AI-likeness.

### Washington HB 1493
- Срабатывает при «enrollment» биометрии в коммерческую базу для идентификации. Если не «enroll» — обычно мимо. AG-энфорсмент.

### Colorado (HB 1130, биометрия)
- Требует **Biometric Identifier Notice** + политику + согласие. Дёшево включить. Часть Colorado Privacy Act.

## 3. Общие privacy-законы штатов (ландшафт 2026)
~20 штатов с comprehensive privacy laws. Применимость — по порогам (обычно ~100k резидентов/год или % выручки от продажи данных).
- **CA CPRA:** биометрия = **sensitive PI**; для <16 — **opt-in на sale/share**; **двойные штрафы за детей, до $7,500/нарушение** (умысел/дети). Право на удаление, opt-out.
- **VA VCDPA / CO CPA / CT CTDPA / UT / TX TDPSA / OR / MT и др.:** для sensitive data (биометрия, дети) — **opt-in consent**; права доступа/удаления/исправления; privacy notice; DPA с процессорами. Детские данные (<13) — повышенная защита, обычно отсылка к COPPA.
- **Действие:** единый Privacy Notice + DSR-механизм (доступ/удаление) + opt-out + не продавать/шарить детские данные.

### CAADCA (California Age-Appropriate Design Code)
- После **NetChoice v. Bonta (9th Cir. 12.03.2026)** — частично в силе (age estimation, default-приватность). **Защита:** age-gate 18+, UX «для взрослых, покупающих подарок», не таргетить детей.

## 4. AI-disclosure
- **US (federal):** жёсткого мандата нет, но **FTC Act §5** карает за введение в заблуждение → раскрывать, что контент/иллюстрация AI-generated. Лёгкая плашка достаточно.
- **EU AI Act Art. 50 (с 02.08.2026):** обязательная маркировка AI-сгенерированных изображений реальных людей — **только если работаете на EU**.

## 5. Международное (если не US-only)
- **GDPR/UK GDPR:** фото ребёнка = ПД ребёнка; биометрия для идентификации = **special category (Art. 9)** → explicit consent; **DPIA обязателен** (Art. 35: дети + биометрия + AI); согласие родителя (Art. 8, порог 13-16 по стране); трансграничная передача → SCCs; EU-представитель (Art. 27). UK — Children's Code (ICO).
- **UAE PDPL:** ребёнок <18; согласие родителя/опекуна; best interests; верификация. (См. `references/uae/pdpl-data-protection.md`.)

## 6. Практическая единая US-позиция (compliance posture)
Для AI-продукта «взрослый загружает фото ребёнка → генерация → печать», **US-only**. Единое общенациональное согласие+раскрытие под стандарт **Illinois BIPA + COPPA покрывает все 50 штатов**:
1. **Age-gate 18+** + позиционирование adult-facing (gift), не на детей.
2. **Согласие ДО загрузки** (unbundled, opt-in, НЕ pre-checked): «Я родитель/опекун 18+ + согласие на обработку фото ребёнка для создания продукта + фото передаётся стороннему AI (назвать) и НЕ хранится».
3. **Не строить идентифицирующий face-template** (защита Zellmer); фото — **transient** (не персистить); эмбеддинги не сохранять.
4. **No-training / zero-retention** режим у AI-провайдера (OpenAI/Replicate) — критично для COPPA. Подтвердить в их ToS.
5. **Письменные retention + security policy**; сгенерированный output (художественный) можно хранить в аккаунте под доступом владельца + удаление по запросу.
6. **Biometric Notice (Colorado)** + лёгкая **AI-disclosure (FTC)**.
7. **DSR:** право удалить аккаунт/данные.
8. **Sub-processors раскрыть** в Privacy Policy (AI-провайдер, печать, платёж, хостинг).
9. Геофенс Illinois — опционально, не обязателен.

## 7. Неочевидные ловушки (children/biometrics)
- Фото ребёнка = «personal information» по COPPA-2025 (faceprint) и «sensitive» по CPRA.
- «Не храним фото» НЕ снимает обязанность согласия ДО сбора (BIPA §15(b)).
- Передача детских данных на обучение AI — НИКОГДА не «integral» (COPPA) → нужен no-training режим.
- Сгенерированное изображение — обычно НЕ биометрия (художественная производная, Zellmer), но остаётся детскими ПД (удаление, security).
- Pre-checked consent = dark pattern + нарушение (BIPA требует affirmative consent).
- Анонимный/детский UX без age-gate → риск «directed to children» → полный COPPA.
